# Context-slot constants: константы замыкания под code dependency

Слайс S. База: `5a2472d2f`. Доказательства: [gate-summary.json](gate-summary.json),
[performance.json](performance.json). Исходники заморожены на весь финальный
гейт и замеры; SHA CLI: `b7a774911aa5091c7d8a80a912d85fa98e645e4bde52f759dff87dbdd200cfaf`.

## Удалённый механизм

Инлайненные методы заново читали привязки замыкания через
`LoadClosureContext`, цепочку `LoadContextParent` и `LoadTaggedField`.
У объекта-константы за этим шли проверки формы перед чтением поля.
Доказанный holder-слот фиксирует одно замыкание: теперь его привязки
становятся `ConstInt32`, `ConstTagged` или чтением traced identity-ячейки,
а контекст читается одним полем замыкания.

- В payload контекста слово `watch` находится по +16, слоты начинаются с +24.
  Аллокация и копирование в VM, Template и Graph обеих архитектур очищают
  watch; moving GC переносит его вместе с контекстом.
- Registry владеет address-stable watches с 64-битной маской слотов и
  подписчиками. Запись в наблюдаемый слот ставит флаги генераций и делает
  привязку volatile для последующих компиляций всех контекстов этого scope.
  Это устраняет повторные специализации изменяемой привязки в новых контекстах.
- Bake исключает hole, undefined, слоты от 64, собственные записи тела и
  volatile-привязки. Moving values удерживает существующая traced identity-ячейка;
  snapshot переносит точный факт ECMAScript Object, включая function ids.
- `CheckContextSlot` становится зависимостью `ContextSlot` и флаговым тестом
  на регион эффектов. Структура стабильного константного объекта также
  защищена dependency, поэтому повторные `CheckShapes` исчезают.
- Каждый writer обслуживает watch: interpreter, Template и Graph arm64/x86.
  Стаб `context_slot_written` — leaf без GC, исключений и reentry. Template
  вызывает его после TDZ-проверки, до store, затем повторно находит контекст;
  Graph уведомляет после store и барьера. Install проверяет актуальность слота.

## Исправления корректности

Выход `DependencyChanged` сразу снимает сработавшие генерации с entry cells;
вызывающие больше не входят повторно в недействительный код.
Template arm64 проверяет watch до store и повторно находит контекст после
leaf-вызова, сохраняя корректность при clobber временных регистров.

GC-ячейка может содержать primitive String, Symbol или BigInt. Такие
константы сохраняют sloppy receiver conversion. Регрессия с 24 000 вызовами
на тип давала в optimizing-коде `[5040,5040,5040,24000]`, тогда как Node,
interpreter и Template давали `[24000,24000,24000,24000]`.
Исправленный финальный CLI совпадает с эталоном во всех режимах. Builder-тест
проверяет primitive cell, object cell и closure-less function id;
регрессия включена в основной corpus и прошла moving/full GC.
