# V8 mechanisms vs Otter's measured gaps

All source links are pinned to tag **15.5.35.10** (commit `cebe537a403f`). `B` = `https://github.com/v8/v8/blob/15.5.35.10/`. Every file, class, function, flag and constant named below was checked against a sparse checkout at that commit. The six most load-bearing citations were also re-fetched from GitHub at the tag. Blog numbers are quoted from v8.dev and were re-checked. Otter-side figures (cell counts, closure counts, ratios, RSS) are Otter measurements that were not re-verified here. Cards are ordered by how much they bear on the measured gaps.

---

### 1. One Context per scope instance, not one cell per binding (earley 110.9M cells, unverified Otter figure)
1. **Source:** `Scope::MustAllocateInContext` in [B/src/ast/scopes.cc#L2630](https://github.com/v8/v8/blob/15.5.35.10/src/ast/scopes.cc#L2630); the `Context` layout comment in `src/objects/contexts.h` (~L451–495); `ConstructorBuiltinsAssembler::FastNewFunctionContext` in `src/builtins/builtins-constructor-gen.cc` L380; the context-slot bytecodes in `src/interpreter/bytecodes.h`. `LdaContextSlot` takes `<ctx reg> <slot> <depth>` and `LdaCurrentContextSlot` / `LdaImmutableCurrentContextSlot` take `<slot>`. Each has a `…NoCell` twin (`LdaContextSlotNoCell`, `LdaCurrentContextSlotNoCell`, `StaContextSlotNoCell`, …). `BytecodeArrayBuilder` emits the `NoCell` form unless `scope()->has_context_cells()`.
2. **Work eliminated:** each scope *instance* with at least one captured (or eval-visible) variable gets one heap object with N slots. Uncaptured variables live in registers. A closure stores **one** context pointer, and creating it copies nothing per binding.
3. **Hot/cold:** read = context register (or frame slot) → `depth` × `ldr previous` → `ldr [ctx+hdr+4*i]` + decompress. Scope entry = one bump allocation plus barrier-free initializing stores (`StoreObjectFieldNoWriteBarrier`). Cold: `with` and sloppy `eval` use `LdaLookupContextSlot*`, which checks the extension objects along the chain. In a context with cells, the cell-aware load also checks for a `ContextCell` and falls back to a builtin.
4. **Invariants:** slot index and depth are compile-time constants from `ScopeInfo`. A variable goes to the context if it is captured (`has_forced_context_allocation`) or if `inner_scope_calls_eval()`. Temporaries are always stack-allocated. Catch variables are always context-allocated. Script and eval lexicals are always context-allocated. TDZ is `the_hole` in the slot. Loop `let` needs a fresh block context per iteration only when it is captured.
5. **GC/exc/deopt:** a Context is an ordinary young object. Frame states carry the context, and the deoptimizer restores it.
6. **Cost:** the object header is map + length, then the two fixed slots `scope_info` and `previous`. That is 4 tagged words, or 16 B with pointer compression. After that comes an optional `extension` slot, then 4 bytes per variable (compressed). It needs no extra compile work because scope analysis already runs in the parser. Known trade-off: a closure keeps the whole context alive.
7. **AOT:** fully static. Offsets are constants and need no relocations.
8. **JS applicability:** this is exactly ES environment-record semantics. Per-binding identity is never observable except through per-iteration copies. V8 did bring back per-slot `ContextCell`s, but only for function contexts with **≤2 slots** (`function_context_cells_max_size`, `flag-definitions.h` L807). The flag comment reads "JS3/UniPoker improves with size >= 2 and SP3/Charts-observable-plot regresses with size > 3". The cells are created lazily on first store (`Context::Set`, `contexts.cc` ~L543) and exist for const and number tracking, not for sharing.
9. **Otter experiment:** on earley-boyer, count scope instances that own at least one captured binding and compare with the 110.9M binding cells. If the ratio is well above 1, prototype a `ScopeEnv{parent, slots[N]}` allocated at scope entry for the top-5 closure-creating functions. Measure retired instructions and GC share.

### 2. Closure creation: `FastNewClosure` + FeedbackCell + dispatch handle (10.2M closures, unverified Otter figure)
1. **Source:** `TF_BUILTIN(FastNewClosure, ConstructorBuiltinsAssembler)` in [B/src/builtins/builtins-constructor-gen.cc#L211](https://github.com/v8/v8/blob/15.5.35.10/src/builtins/builtins-constructor-gen.cc#L211); `CreateClosureFlags::Encode` in `src/interpreter/bytecode-flags-and-tokens.cc` L32; `JSCreateLowering::ReduceJSCreateClosure` in `src/compiler/js-create-lowering.cc` L947; `MaglevGraphBuilder::VisitCreateClosure` (L14313) → `FastCreateClosure` node; `JSDispatchTable` in `src/sandbox/js-dispatch-table.h` (~L165).
2. **Work eliminated:** on the fast path there is no runtime call, no per-capture copy and no old-space placement. The fast path runs when `CreateClosureFlags::Encode` sets `FastNewClosureBit`, which it does only when the closure is not pretenured *and* is in a function scope. A closure without a prototype slot (arrows, methods) is `JSFunctionWithoutPrototype::kMinSize == 7*kTaggedSize` (28 B): map, properties, elements, feedback_cell, SFI, context, dispatch_handle. An ordinary `function` is `JSFunctionWithPrototype` at 8×kTaggedSize (32 B), because it adds `prototype_or_initial_map`. The code comes from a **shared dispatch-table entry**, so tier-up updates one entry for all closures of that function. Per the header comment, this avoids a tier-up check on every invocation.
3. **Hot/cold:** the builtin tests the FeedbackCell map (NoClosures→One is a store; Many does nothing), decodes the function-map index from the SFI flags, loads the map from the native context, bump-allocates, and does about 7 initializing stores (root or no-write-barrier). Turbofan inlines the allocation only when the cell is `many_closures_cell_map` and the function is not a class constructor. It then **always uses `AllocationType::kYoung`**, and a comment says it deliberately ignores the parser's pretenure bit (crbug.com/810132). Lower tiers honor that bit. When `FastNewClosureBit` is clear, Ignition, Sparkplug and Maglev call `Runtime::kNewClosure` or, when pretenured, `Runtime::kNewClosure_Tenured`. Cold: One→Many tail-calls `Runtime::kNewClosure`, because code may be context-specialized to the single closure.
4. **Invariants:** there is one FeedbackCell per creation site per native context, and it acts as a 0/1/many closure counter. The dispatch entry's parameter count must match its code.
5. **GC:** young allocation on the fast path. The dispatch handle is a table index, and the table does not compact (`static_assert(!kSupportsCompaction)`).
6. **Cost:** 28 B per closure without a prototype slot, 32 B with one (plus any in-object properties from the map). The context, SFI and cell are shared.
7. **AOT:** the SFI becomes static metadata. The dispatch entry becomes a GOT-like writable slot per function, so code needs no patching.
8. **JS limits:** an ordinary non-arrow `function` gets `prototype_or_initial_map = the_hole` (lazy prototype). Class constructors are never inlined.
9. **Otter experiment:** allocate earley closures in the nursery through an inline bump in Template/Machine code, with body `{shape, fn-meta, env}`. Measure instructions, GC share and RSS against the current old-space runtime call.

### 3. Inline bump allocation, allocation folding, write-barrier elision (ast_ctor, earley, zlib RSS)
1. **Source:** `MemoryAnalyzer` (L93, with `IsPartOfLastAllocation` at L129 and `SkipWriteBarrier` at L140) and `MemoryOptimizationReducer` (L188, `REDUCE(Allocate)` at L250) in [B/src/compiler/turboshaft/memory-optimization-reducer.h](https://github.com/v8/v8/blob/15.5.35.10/src/compiler/turboshaft/memory-optimization-reducer.h); Turbofan `MemoryLowering::AllocationGroup` in `src/compiler/memory-lowering.h`; Maglev `AllocationBlock` and `InlinedAllocation` in `src/maglev/maglev-ir.h` (L6631/L6411), with `AllocationBlock::GenerateCode` → `MaglevAssembler::Allocate` (`maglev-ir.cc` L4937); flag `maglev_allocation_folding=2`.
2. **Work eliminated:** a runtime call and a limit check per object. A folded group needs **one** limit check. Write barriers disappear for stores into the newest young allocation (`IsPartOfLastAllocation`, including allocations folded into it) and for values that need no barrier (`!ValueNeedsWriteBarrier`).
3. **Hot/cold:** `top=[top_addr]; cmp top+RESERVE,[limit]; b.hs slow; …; [top_addr]=top+size; obj=top+1`, then plain stores. Cold: call the `Allocate*` builtin, which may GC.
4. **Invariants:** allocations fold only when nothing between them can allocate. Sizes must be constant and ≤`kMaxRegularHeapObjectSize`. Objects are fully initialized before the next observable point (`AllocationBuilder` wraps allocation and init in `BeginRegion(kNotObservable)`/`FinishRegion`). Barrier elision applies only while the last allocation is `kYoung`: a new young object cannot be an old→young source and has not yet been scanned by the marker.
5. **GC/deopt:** the slow path is a safepoint. No deopt can happen inside a region.
6. **Cost:** a skipped branch wastes its reserved tail. The analysis is a single forward pass.
7. **AOT:** top/limit are reached through the isolate/root register, never absolute addresses.
8. **JS:** applies to any fixed-shape allocation: objects from a known initial map, contexts, closures, literal arrays, HeapNumbers.
9. **Otter experiment:** the rejected "young binding cells" run (+6.27% instructions, unverified Otter figure) still went through the Rust runtime and kept per-cell objects. Separate the causes: JIT-inline young allocation for one hot type with barrier-free init stores. Count instructions per allocation (target ≤10) and scavenge survival.

### 4. In-object slack tracking, `JSCreate` lowering, AllocationSite pretenuring (ast_ctor)
1. **Source:** `Map::kSlackTrackingCounterStart = 7` and `IsInobjectSlackTrackingInProgress` in [B/src/objects/map.h#L403](https://github.com/v8/v8/blob/15.5.35.10/src/objects/map.h#L403); `JSCreateLowering::ReduceJSCreate` (`js-create-lowering.cc` L115) using `DependOnInitialMapInstanceSizePrediction`; `PretenuringHandler`, `MakePretenureDecision` and `DigestPretenuringFeedback` in `src/heap/pretenuring-handler.cc` (L44/L77; `kMinMementoCount=100`, `kScavengerPretenureRatio=0.80`); paper [Memento Mori: Dynamic Allocation-Site-Based Optimizations, Clifford/Payer/Stanton/Titzer, ISMM'15](https://research.google.com/pubs/archive/43823.pdf).
2. **Work eliminated:** the first 7 `new C` over-allocate in-object slots, then the instance size shrinks to what was used. After that, every constructor property is in-object with no out-of-line backing store. Optimized `new C` is one inline allocation of the exact predicted size, with `undefined`-filled in-object fields. An allocation site gets pretenured (allocated old directly, which avoids copying) when at least 100 mementos have been created and the mementos found during scavenge divided by mementos created is ≥0.80. Put simply, ≥80% of the sampled allocations from that site were still alive at a scavenge. Under MinorMS the threshold scales with new-space capacity.
3. **Hot/cold:** same as card 3. Unoptimized literal allocation appends an `AllocationMemento`; the scavenger finds it with `FindAllocationMemento`.
4. **Invariants:** the size prediction is a compilation dependency. A tenure decision flips `set_deopt_dependent_code` (group `kAllocationSiteTenuringChangedGroup`).
5. **GC:** mementos are only read during scavenge.
6. **Cost:** 2 extra words per tracked literal allocation in lower tiers.
7. **AOT:** instance size can be computed statically from class fields and `this.x=` in the constructor (a per-class closed world). Pretenuring is profile-driven, so it needs PGO or a data-driven flag in the allocation stub.
8. **JS limits:** `delete` or too many properties → dictionary map. Slack tracking covers `new`-constructed objects. Allocation-site feedback covers literal boilerplates.
9. **Otter experiment:** on ast_ctor, measure bytes per node and the share of properties stored out-of-line. Add a per-constructor construction counter that shrinks and fixes the instance size, then measure instructions and RSS.

### 5. Escape analysis, including contexts (earley, ast_ctor)
1. **Source:** Turbofan `EscapeAnalysis` and `ReduceNode` in [B/src/compiler/escape-analysis.cc#L634](https://github.com/v8/v8/blob/15.5.35.10/src/compiler/escape-analysis.cc#L634), plus `EscapeAnalysisReducer::ReduceFrameStateInputs`/`ObjectIdNode`; Turboshaft `LateEscapeAnalysisAnalyzer` (`late-escape-analysis-reducer.h`: "removes allocation that have no uses besides the stores initializing the object"); Maglev `InlinedAllocation`/`VirtualObject` with `RunEscapeAnalysis` in `src/maglev/maglev-post-hoc-optimizations-processors.h` L474; `MaglevGraphBuilder::TryBuildInlinedAllocatedContext` (contexts of length ≤16, `kContextAllocationLimit`, become virtual objects allocated `kYoung`), `MinimizeContextChainDepth` (L187) and `EscapeContext` (L198).
2. **Work eliminated:** allocation, field stores and field loads of non-escaping objects, **including function/block contexts**. Context-slot loads become SSA values, and context-chain walks fold away through graph parents.
3. **Hot/cold:** nothing is emitted on the hot path. Deopt materializes the objects.
4. **Invariants:** constant size, and every use is a constant-offset field access or a frame-state use. In Maglev, escaping propagates to dependencies until a fixpoint (`EscapeAllocation`). Turbofan escapes BoundedSize and TrustedHeapConstant fields.
5. **GC/deopt:** frame states reference virtual objects as `CAPTURED_OBJECT`/`DUPLICATED_OBJECT`. `TranslatedState::EnsureCapturedObjectAllocatedAt`/`InitializeCapturedObjectAt` allocate them at deopt, so the deopt path must be GC-safe.
6. **Cost:** Turbofan's analysis is an iterative whole-graph pass. Maglev's is a cheap use-marking pass.
7. **AOT:** sound without speculation. Materialization is needed only if AOT code can deopt.
8. **JS limits:** any non-inlined call escapes its arguments, and getters and Proxy traps are calls. `arguments`/eval escape the context.
9. **Otter experiment:** with card 1 in place, measure the share of earley env objects whose uses are all inlined in Machine code. Check that partial escape elides env + closure pairs such as `forEach(x => acc += x)`.

### 6. Context specialization and `ContextCell` constness (crypto, fib, earley helpers)
1. **Source:** `JSContextSpecialization::ReduceJSLoadContextNoCell` (L185) / `ReduceJSLoadContext` (L248) in [B/src/compiler/js-context-specialization.cc#L185](https://github.com/v8/v8/blob/15.5.35.10/src/compiler/js-context-specialization.cc#L185). The gate is in `src/compiler/pipeline.cc` L720–733. It requires three things: the SFI is not `function_context_independent_compiled()`, the closure's FeedbackCell map is `one_closure_cell_map`, and the compilation is not OSR. Also: `SpecializeToFunctionContext` in `src/maglev/maglev-compilation-info.cc` (L50); `ContextCell::State {kConst,kSmi,kInt32,kFloat64,kDetached}` in `contexts.h` L952; flags `script_context_cells` and `function_context_cells`; [mutable heap numbers blog, 25 Feb 2025](https://v8.dev/blog/mutable-heap-number) (~2.5× async-fs, ~1.6% JetStream2).
2. **Work eliminated:** context-chain loads become a heap constant. Immutable or `kConst` slots become constants, so captured helper functions become direct, inlinable calls. `kInt32`/`kFloat64` cells update in place with no HeapNumber allocation per write.
3. **Hot/cold:** no loads for constants. `kSmi`/`kInt32`/`kFloat64` cells become typed field loads. Cold: a state change calls `NotifyContextCellStateWillChange` → deopt of dependent code.
4. **Invariants:** valid only while one closure exists (FastNewClosure's One→Many transition goes to the runtime). Even an "immutable" slot is folded only if it is currently neither hole nor undefined, because the context may escape before initialization. Dependency group: `kContextCellChangedGroup`.
5. **GC:** heap constants are embedded through reloc info (`COMPRESSED_EMBEDDED_OBJECT`) and traced from code.
6. **Cost:** code cannot be shared across closures. That is acceptable because there is only one closure.
7. **AOT:** object-identity specialization is impossible. The AOT-compatible subset is static never-reassigned analysis (`const`, never-written `let`) and module-level singletons.
8. **JS limits:** eval, `with` and the debugger can write slots, which V8 handles through cell states and deopt.
9. **Otter experiment:** count dynamic loads of captured bindings in hot Machine code whose binding is never written after init. Fold them for single-closure functions (reuse the settled global-lex mechanism) and measure crypto and earley.

### 7. Maps include the prototype; prototype validity cells; stub cache (ts 9.4×, mega_method 2.5×, unverified Otter figures)
1. **Source:** the Map layout table in [B/src/objects/map.h#L176](https://github.com/v8/v8/blob/15.5.35.10/src/objects/map.h#L176) (`[prototype]` L235, `[prototype_validity_cell]` L247, `[prototype_info]` L250); `Map::GetOrCreatePrototypeChainValidityCell` L583; `Map::IsPrototypeValidityCellValid` (`map-inl.h` L1170); `JSObject::InvalidatePrototypeChains` (`js-objects.cc` L5384); `PrototypeInfo::prototype_users` (`prototype-info.h`); `MapUpdater`; `StubCache` with `kPrimaryTableBits=12` and `kSecondaryTableBits=10` (`src/ic/stub-cache.h` L88–90); `AccessorAssembler::GenerateLoadIC_Megamorphic`.
2. **Work eliminated:** one map compare also proves prototype identity. A prototype-chain hit needs one validity-cell check at any chain depth, instead of a guard per hop. Megamorphic sites do one hashed (map, name) probe into a (map, name, type) → handler cache.
3. **Hot/cold:** IC = `cmp map; ldr cell; ldr value; cmp invalid` → load from the holder. Optimized code emits **no check** (`DependOnStablePrototypeChains` + deopt). The cost moves to the mutation side: invalidation walks the downstream `prototype_users`.
4. **Invariants:** prototype objects get dedicated maps (`is_prototype_map`, `OptimizeAsPrototype`), so any prototype mutation invalidates its cell. `kNoValidityCellSentinel` (`Smi::zero()`) is used when the direct prototype is null or a Proxy.
5. **GC:** `prototype_users` is a `WeakArrayList`.
6. **Cost:** a map per prototype object. Transition trees share `DescriptorArray`s (`owns_descriptors`).
7. **AOT:** maps and the stub cache exist only at runtime. AOT code must keep IC state in data (a feedback vector), not in patched code.
8. **JS:** `setPrototypeOf` forces a map change, and the same layout under different prototypes means different maps (more polymorphism). Proxy has no fast path. Getters go through accessor handlers.
9. **Otter experiment:** Otter shapes lack the prototype. Add the prototype to Shape, plus one validity cell per prototype shape. Count guards per proto-chain load in Machine code, and measure mega_method and ts-fixed.

### 8. Calling convention: reversed args + argc slot (no adaptor frame) + dispatch table (fib 4×, unverified Otter figure)
1. **Source:** `StandardFrameConstants` (`kFunctionOffset`, `kArgCOffset`) in [B/src/execution/frame-constants.h#L109](https://github.com/v8/v8/blob/15.5.35.10/src/execution/frame-constants.h#L109); `LeaveInterpreterFrame` in `src/builtins/arm64/builtins-arm64.cc` L1012; [adaptor-frame blog, 15 Feb 2021, V8 8.9](https://v8.dev/blog/adaptor-frame) (EarleyBoyer +6.1%, Richards +4.6%, Turbofan microbenchmarks up to 40%); `JSDispatchTable` comment block.
2. **Work eliminated:** the extra frame on arity mismatch, the tier-up check at every entry, and per-closure code-pointer updates.
3. **Hot/cold:** arguments are pushed reversed, so parameter i sits at a fixed fp offset. The caller loads `dispatch_handle`, then entrypoint + parameter_count from the table. If there are too few arguments, `undefined` is pushed. The callee's fixed header stores `argc`, and on return pops `max(argc, formal)`.
4. **Invariants:** parameter offsets do not depend on argc. The argc slot is what `arguments`/rest read.
5. **GC:** argument slots are tagged and are visited through the caller's frame iteration.
6. **Cost:** one header word.
7. **AOT:** direct calls for known targets. The table indirection is needed only for dynamic or tiering calls.
8. **JS:** covers over/under-application, `arguments`, rest parameters and legacy `f.arguments`.
9. **Otter experiment:** on fib, count instructions per call from the call op to the callee's first op in each tier. Look for per-call arity copies and entry tier-up counters.

### 9. Deopt translations and safepoint tables (compile-time/memory for all speculation)
1. **Source:** `TranslationOpcode` list in [B/src/deoptimizer/translation-opcode.h](https://github.com/v8/v8/blob/15.5.35.10/src/deoptimizer/translation-opcode.h) (`INTERPRETED_FRAME_WITH_RETURN`, `CAPTURED_OBJECT`, `DUPLICATED_OBJECT`, `INT32_REGISTER`, `MATCH_PREVIOUS_TRANSLATION`, …); `DeoptimizationFrameTranslation`/`DeoptimizationData` in `src/objects/deoptimization-data.h`; `Deoptimizer::kFixedExitSizeMarker`, with `kEagerDeoptExitSize = kInstrSize` on arm64 (`deoptimizer-arm64.cc` L15; lazy exits are 1 or 2 instructions depending on CFI); `Deoptimizer::DoComputeUnoptimizedFrame`/`MaterializeHeapObjects`/`DeoptimizeMarkedCode`; `DependentCode` groups; `SafepointEntry` (tagged-slot bitmap + `tagged_register_indexes`), `MaglevSafepointEntry` (just `num_tagged_slots` because tagged spills are laid out first) and `MaglevFrame::Iterate` (`frames.cc` L2173).
2. **Work eliminated:** an eager exit is **one call instruction**, and the deopt index is derived from the return address. Translations are deduplicated. Lazy deopt costs nothing on the hot path. Maglev's stack map is O(1) per safepoint.
3. **Hot/cold:** a guard is `cmp; b.cond exit`. The deoptimizer interprets the translation, materializes numbers and objects, and builds interpreter frames.
4. **Invariants:** every speculation point has a frame state covering the innermost and inlined frames (registers, accumulator, context, untagged int32/float64, literals, captured objects).
5. **GC/exc:** materialization allocates, so the deoptimizer runs at a GC-safe point. Tagged-ness is exact per safepoint.
6. **Cost:** bytes per translation. V8 accepts a larger side table in exchange for tiny code.
7. **AOT:** an AOT artifact that deopts must ship bytecode, translations and an interpreter. The alternative is AOT without speculation.
8. **JS:** required for any map, Smi or hole speculation.
9. **Otter experiment:** on ts-fixed, measure per-function exit-stub bytes and metadata bytes. Try table-driven single-instruction exits and measure code size and compile time.

### 10. Sparkplug: baseline compiled straight from bytecode, same frame
1. **Source:** `BaselineCompiler` (`GenerateCode`, `VisitSingleBytecode` L544, `bytecode_offset_table_builder_`) in [B/src/baseline/baseline-compiler.cc](https://github.com/v8/v8/blob/15.5.35.10/src/baseline/baseline-compiler.cc); `BaselineBatchCompiler`; [Sparkplug blog, 27 May 2021](https://v8.dev/blog/sparkplug) ("interpreter-compatible frames", Speedometer +5–10%).
2. **Work eliminated:** dispatch and decode. It has no IR and no register allocation because it reuses the bytecode register file. OSR between interpreter and baseline needs no frame translation. It shares the same feedback vector.
3. **Hot:**
   - `VisitLdaContextSlot` (L893) walks the depth, loads the slot, and checks for `CONTEXT_CELL_TYPE`, falling back to the `LoadFromContextCell` builtin. `VisitLdaContextSlotNoCell` (L884) is the plain load.
   - `VisitCreateClosure` (L2467) calls the `FastNewClosureBaseline` builtin when `FastNewClosureBit` is set. Otherwise it calls `Runtime::kNewClosure` or `kNewClosure_Tenured`.
   - Most operations call builtins.
4. **Invariants:** frame layout is identical to the interpreter's. The pc-to-bytecode-offset table serves the stack walker, exceptions and deopt targets.
5. **GC:** every register-file slot is tagged, so no safepoint table is needed.
6. **Cost:** a linear pass. Code is several times the size of the bytecode.
7. **AOT:** this is the natural portable baseline: bytecode compiled in a linear pass to calls into isolate-independent builtins.
8. **JS:** 1:1 with bytecode semantics.
9. **Otter experiment:** confirm the Template frame is byte-identical to the interpreter frame. Measure instructions per bytecode for earley's top-10 functions.

### 11. Embedded builtins + bytecode-only code cache (AOT substrate)
1. **Source:** `EmbeddedData` in [B/src/snapshot/embedded/embedded-data.h#L55](https://github.com/v8/v8/blob/15.5.35.10/src/snapshot/embedded/embedded-data.h#L55); `EmbeddedData::NewFromIsolate` and `EnsureRelocatable` (only `CONST_POOL` reloc allowed) in `embedded-data.cc` L224+; `platform-embedded-file-writer-*.cc`; `CodeSerializer::SerializeObjectImpl`, which does `CHECK(!IsInstructionStream)` (`code-serializer.cc` L118–131); [embedded builtins blog, 14 Aug 2018](https://v8.dev/blog/embedded-builtins) (−19% median V8 heap, ~0.5% Speedometer 2.0 cost).
2. **Work eliminated:** per-isolate builtin copies, startup relocation, and machine code in caches. The code cache holds bytecode and SFIs only.
3. **Hot:** builtin calls are pc-relative or go through the builtin table off the root register. Roots are root-register-relative.
4. **Invariants:** builtins embed no heap pointers. Read-only roots sit at static offsets.
5. **GC:** off-heap code is never moved or scanned.
6. **Cost:** one indirection for constants.
7. **AOT:** this is the template for Otter's JS→native object: the same "no absolute heap pointers" rule applied to user code.
8. **JS:** not applicable.
9. **Otter experiment:** emit Otter's runtime stubs into one `.o`, count relocation kinds, and measure startup.

### 12. Pointer compression + 31-bit Smi (zlib RSS 795 MB vs 80 MB, unverified Otter figure)
1. **Source:** `V8HeapCompressionSchemeImpl::CompressObject`/`DecompressTagged` in [B/src/common/ptr-compr.h#L23](https://github.com/v8/v8/blob/15.5.35.10/src/common/ptr-compr.h#L23); `kPtrComprCageReservationSize` (4 GB) and `SmiValuesAre31Bits` in `include/v8-internal.h` L167/L194; [pointer-compression blog, 30 Mar 2020](https://v8.dev/blog/pointer-compression) (V8 heap up to −43%; double-field unboxing disabled because it cannot coexist with pointer compression).
2. **Work eliminated:** half the bytes per tagged field, which halves cache traffic and scavenge copy/scan bytes. Small ints are never boxed.
3. **Hot:** decompress = `add x, base, w` (unconditional add, "Smi-corrupting").
4. **Invariants:** everything lives in the cage and the base stays in a register.
5. **GC:** 4-byte slots, updated in place on move.
6. **Cost:** double fields are boxed HeapNumbers, mutable in place.
7. **AOT:** a base-register convention plus `COMPRESSED_EMBEDDED_OBJECT` relocs.
8. **JS:** a 4 GB cage per heap.
9. **Otter experiment:** Otter already has 4-byte references but 8-byte NaN-boxed `Value` slots. Measure the zlib/ts heap bytes held in Value slots that contain references or int32 values. A 2× slot saving cannot explain 10× RSS, so profile survivor volume first (cards 2–3).

### What V8 does not spend that Otter spends
- **A heap object per captured binding.** V8 uses one Context per scope instance, none when nothing is captured, and lazy cells only in ≤2-slot function contexts.
- **Runtime calls and old-space placement for closures, contexts and constructor objects.** V8 bump-allocates them in the young generation. Closures take the `FastNewClosure` builtin on the non-pretenured function-scope path, and Turbofan inlines them. Turbofan's inline closure allocation ignores the parser's pretenure hint, although lower tiers honor it.
- **Write barriers and remembered-set entries.** V8 skips the barrier on initializing stores to fresh young objects, and so avoids remembered-set entries from old cells that point at young values.
- **Per-hop prototype guards.** V8 does one map check, which implies the prototype, plus one validity cell, or zero checks with a dependency.
- **Call and tiering overhead:** a tier-up check at every function entry, adaptor frames, and interpreter↔baseline frame translation.
- **Per-exit deopt code.** A V8 eager exit is one instruction backed by shared, deduplicated translations.
- **HeapNumber allocation on every number write to hot context slots.** V8 uses `kInt32`/`kFloat64` cells.
- **Machine code in the code cache, and per-isolate builtin copies.**
- **8-byte tagged slots.**
