# Otter — жёсткий рефакторинг, раунд 3: wall-clock, конкурентность, весь движок

Ты — инженер VM/компилятора. Последние сутки ушли на цепочку локальных JIT-срезов
(push/pop, рост слаба, вклейка конструкторов, пилинг циклов, `.length`,
typed-store): геосреднее fixed-work инструкций 2.319→2.143 (−7.6%) за 7 коммитов
по ~50 минут гейта каждый. Это выжимание процентов внутри одной оси. Так дальше
нельзя. Этот раунд:

1. меряет **скорость** (wall-clock), а не только retired instructions;
2. атакует **архитектурные** разрывы, которые инструкции не видят вообще;
3. правит **весь движок**. Защищённых подсистем нет. Под пересмотр и замену идут:
   - GC и модель потоков;
   - все тиры JIT, interpreter и байткод;
   - объектная модель, runtime и builtins;
   - строки, regex, модули и загрузчик;
   - async, event loop, I/O;
   - startup, память, CLI и PM.

   Каждая подсистема получает свой замер против node и bun. Чинится то, где
   мы проигрываем, в порядке wall-clock цены. Направления A–F ниже — первая
   очередь, а не граница охвата.

Внутренние breaking changes разрешены: API, ABI, раскладки объектов, байткод,
форматы артефактов меняются на месте, все producer/consumer/тесты обновляются
вместе. Сохраняются семантика JS, GC-safety и capability-проверки. Один
внутренний контракт: никаких версий, мостов, совместимых дубликатов,
generic-call обходов.

14.9 / 27.6 / 7.0 ms.

Выводы, которые инструкции прятали:

- **Wall-clock разрыв больше инструкционного**: 2.52x против 2.14x к node.
  ts: 3.27x по времени против 1.77x по инструкциям; navier и zlib «быстрее node»
  по инструкциям, но медленнее по времени.
- **Otter однопоточен, конкуренты — нет.** У otter user ≈ wall. У node и bun
  user заметно больше wall: ts node user 2200 / wall 1134, ts bun 2618 / 954,
  splay bun 481 / 182, gbemu node 689 / 465. Конкуренты гоняют GC (marking,
  sweeping, scavenge) и компиляцию на фоновых потоках. Retired instructions
  суммируют все потоки, поэтому эту работу они не наказывают — а wall-clock
  наказывает нас. Это крупнейший невидимый разрыв, и ни один JIT-срез его не
  закроет.
- **Память**: splay — 988 MB RSS против 366 у node и 215 у bun, 101 ms sys.
  GC и рост кучи — отдельная ось, а не шум.
- **Runtime, а не JIT**: regexp — 69% сэмплов в vm-runtime. Из них ~13% —
  `jit_resolve_method_stub`: вызов метода на строковом примитиве
  (`str.replace(…)`, 712 сайтов в бенче) не кешируется **ни в одном тире**,
  потому что load IC не умеет примитивный receiver
  (`emit_select_entry` в `crates/otter-jit/src/arm64/property_ic.rs`,
  `method_site_for_receiver` требует object). Также gbemu: `otter_native_invoke`
  — заметная доля runtime. Стоимость вызова native — отдельная ось.
- bun падает на crypto/navier-stokes/gbemu/zlib (фикстуры — sloppy scripts,
  например `ReferenceError: setupEngine`). Сравнение с bun неполное, пока нет
  честной обёртки.

## Шаг 0 — закрыть висящий срез (без новых правок кода)

В рабочем дереве лежит срез `typed-view-store`, гейт attempt 1 полностью
зелёный:
- test262 52463/12 fail, набор падений = `full-2026-10-12g`, отчёт `full-2026-10-12h`;
- difftest host и x86 156/0;
- VM/JIT lib, clippy host/x86;
- oracle корпусов во всех режимах + GC stress;
- GC256 на всех 13.

Содержимое среза:
- generic keyed store пишет Number в typed view любого не-BigInt вида inline
  (ARM `crates/otter-jit/src/graph/arm64/keyed_store.rs`, x86
  `x86_64/keyed_store.rs`, дескриптор `JitTypedArrayStorage` в `otter-vm/src/jit.rs`);
- баг-фикс VM: значения ≥ 2^63 в Int8/Uint8/Int16/Uint16, DataView, Atomics
  насыщались вместо ToInt32 по модулю 2^32.

Осталось: FW all-13 + `scripts/dev/wallclock_matrix.sh`, `summary.md` в
`benchmarks/results/typed-view-store/`, G-коммит, `rm -rf target/x86_64-apple-darwin`.

## Направления (крупные рефакторинги, порядок — по измеренной wall-clock цене)

Каждое направление — архитектурная замена с удалением старого механизма, а не
серия микросрезов. Перед проектированием прочитай, как это устроено в
`~/work/engines/*` (исходники, не пересказ): какой инвариант, какой протокол
потоков, какие барьеры. В коде, комментариях и коммитах движки не называть
(Bun можно).

**A. Конкурентность: фоновая компиляция.**
- Оптимизирующая компиляция уходит с главного потока. Снапшот
  (`JitCompileSnapshot`) уже «заморожен» на границе — доведи его до
  thread-safe владения.
- Установка кода — на safepoint с проверкой эпох feedback/зависимостей;
  устаревший результат выбрасывается.
- Измеритель: время компиляции на главном потоке → ~0; crypto/ts wall.

**B. Конкурентность: GC.**
- Параллельный scavenge (несколько потоков эвакуируют молодое поколение).
- Конкурентный marking старого поколения: write barrier уже знает флаг
  marking; нужен корректный протокол snapshot-at-the-beginning или
  incremental-update.
- Конкурентный/ленивый sweeping.
- Доказательство корректности корней и барьеров — до кода. Проверка под
  `OTTER_GC_STRESS` и на all-13.
- Запрет на `thread_local`/`static mut`/process-global остаётся: состояние
  per-isolate (Interpreter/heap), потоки — пулом изолята.

**C. Память и форма кучи.**
- splay 988 MB: найди, что раздувает — размер nursery и порог promotion,
  выживаемость, слабы элементов, фрагментация old space, удержание.
- Харнесс: retained heap и распределение пауз GC (p50/p99/max). Не путать с
  max RSS. Нужна диагностика без новых env-флагов: CLI-вывод или
  существующий профайлер.

**D. Runtime-слой и встроенные функции.**
- Примитивные receiver'ы в IC-субстрате. Строка → `%String.prototype%`
  (dictionary-holder, доказательство `JitMethodHolder::Dictionary`), один
  механизм для interpreter, template и graph. Удаляет resolve-stub на
  строковых методах.
- Стоимость вызова native (`otter_native_invoke`, `call_generic_entry`):
  один протокол без Rust-реентри там, где native — лист.
- Протокол RegExp (`exec`/`replace`/`split` через Symbol-методы), строки
  (concat/ropes/flatten), `Map`/`Set`, JSON. Regex JIT запрещён — работай над
  матчером, протоколом и аллокациями вокруг него.

**E. Остальной движок — проверить, не только JIT.**
- Startup: 12.1 ms против 7.0 у bun.
- Загрузка модулей и `node_modules`; async/Promise/microtasks; таймеры и I/O;
  typed arrays/DataView; interpreter и template на холодном коде; время
  компиляции.
- Для каждого — workload вне Octane. Сначала объяви матрицу: ts-компилятор,
  JSON-тяжёлый, async I/O, старт с зависимостями, реальный regex-код, большие
  аллокации. Затем замер всех трёх движков.
- bun-обёртка для sloppy-фикстур, чтобы сравнение было полным.

**F. JIT — только структурно.**
- Допустимо, если закрывает измеренную долю ≥5% wall на workload или удаляет
  механизм. Примеры:
  - метод-константа под validity вместо загрузки через holder (deltablue,
    `LoadGuardedMethod`);
  - полиморфный elements-kind dispatch в feedback вместо Generic.
- Не повторять тупик dependency-mode / post-call invalidation.

## Протокол измерений (обязателен)

- **Первичная метрика — wall-clock.** `scripts/dev/wallclock_matrix.sh <otter> <out> 5`:
  медиана ≥5 свежих процессов, warmup, ротация порядка, node и bun рядом,
  user/sys в JSON. Увеличивай число прогонов, если разница в пределах разброса.
- Вторично: peak RSS (там же), retired instructions
  (`scripts/dev/fw_vs_node.sh`). Инструкции — диагностика оверхеда, не
  критерий успеха. Node-числа в `node-instructions.txt` — записанные; при
  сравнении перемерь.
- Отдельно: startup (hyperfine, 20 прогонов), паузы GC, retained heap,
  компиляция.
- Каждый отчёт среза: таблица wall + RSS + инструкции по всем фикстурам,
  регрессии перечислены явно (сверх разброса). Никаких измерений во время
  сборок и раннеров.
- Профиль упорядочивает работу, но не заменяет причинное объяснение:
  профиль → сгенерированный/runtime-код → причина → архитектурное решение →
  wall-clock дельта.

## Обязательные правила (без изменений)

- **VCS.** Только `main`. Без worktree, stash, checkout, reset. Откат своего —
  только точечный `git apply -R`. Untracked-файлы пользователя сохранять
  (особенно `scripts/dev/hot_asm.py`).
- **Правки кода.** Не править исходники во время сборки и во время гейта.
  rustfmt только для листовых файлов, никогда `lib.rs`.
- **Тесты.** Никакого `cargo test --workspace`; не больше 1–2 runtime `--test`.
  Тестов минимум: корпус difftest вместо пачек unit-тестов.
- **Без костылей.** Новые env-флаги, feature-флаги, `thread_local`,
  `static mut`, process-global запрещены. Пробы убирать до коммита.
- **Баги.** Найденный баг — чинить сразу (fix forward). Все падения наши.
- **Проверка каждой оптимизации:** difftest-корпус, `--interpreter`-оракул,
  Node.
- **Где лежат файлы.** Пробы, патчи, результаты — в `scripts/dev` и
  `benchmarks/results/<slice>/`, не в /tmp.
- **Гейт на срез (формат не менять):**
  - test262 safe runner — один, в фоне, `timeout: 7200000`, те же 12 fail;
  - difftest host/x86 `--timeout-ms 120000`;
  - release x86 build;
  - GC256 на всех 13;
  - clippy host/x86 `-D warnings`;
  - VM/JIT `--lib --release`;
  - плюс wall-clock матрица.
- **Коммиты.** Только GPG-подписанные, проверка `%G?` = G. Без AI-трейлеров и
  Co-Authored-By. Без «не сделано / остаётся» в тексте. Коммит — отдельным
  вызовом после проверки вывода тестов.
- **После G-коммита:** `rm -rf target/x86_64-apple-darwin` (не
  `cargo clean --target`).
- **Документы.** Никаких design-doc файлов. Отчёт среза — `summary.md` с
  цифрами.

## Критерий раунда

- Геосреднее wall-clock к node и к bun (по всем фикстурам, которые запускает
  каждый движок) и startup падают за счёт закрытых осей A–D, а не суммы
  микросрезов.
- Splay RSS — в пределах 1.5x от node.
- regexp — без resolve-stub в профиле.
- Каждый срез называет удалённый механизм и измеренную wall-clock дельту.
