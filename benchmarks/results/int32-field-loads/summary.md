# Int32 fields: чтение числового payload под dependency

База: `8cdb80bd5`. Доказательства: [gate-summary.json](gate-summary.json),
[performance.json](performance.json). Исходники заморожены на финальный gate и
все замеры; SHA CLI: `a4e0809742f2f21a7a5c9ca3ce0156b0ccb1c24af5892c0ed26186df32a1c930`.

## Удалённый механизм

Загрузка обычного числового поля возвращала tagged-значение, после чего
каждый арифметический потребитель повторно проверял тег и извлекал Int32.
Теперь defining shape наблюдает Int32 как отдельную категорию. Точный
summary `INT32` разрешает Graph читать четыре байта payload сразу в Int32
под существующей зависимостью `FieldType`.

- Все VM writers, рождения объектов и native-пробы обеих архитектур
  поддерживают одну текущую решётку. Float64, остальные примитивы и широкие
  объединения дают absorbing Top; смесь Int32 с объектом не даёт result-shape
  proof, но сохраняет исторические shape targets для store membership.
- Builder требует owner proof у исходной загрузки. Полученный Int32
  проходит SSA без повторного `CheckedTaggedToInt32`; смена категории
  ставит флаг generation и возвращает выполнение к исходной операции.
- ARM64 использует `LDR W`, x86 — 32-битный `MOV`. Обе банки читают текущий
  handle; адрес storage не становится SSA-значением. Граница scaled-offset
  для ARM64 пересчитана под ширину четыре байта и проверена исполняемым тестом.
- Доказанная числовая запись в owner, уже содержащий Int32, не выбирает
  observer и не генерирует membership-пробу. Остальные записи используют
  captured/live membership и тот же noncollecting VM leaf при widening watch.

## Корректность

Новый корпус покрывает inline/suffix поля, numeric widening, nullish/object
и string values, переполнение, native stores, Reflect/descriptor mutations,
data → accessor и array expando. Чтение accessor повторено 100 000 раз.

Этот сценарий выявил ошибку существующего Template inlining: bake находил
receiver slot по имени, не проверяя descriptor, и после retraining читал
сырой accessor cell вместо вызова getter. Baker вынесен из oversized
`jit_compile.rs` в `jit_inline_methods.rs`. Он принимает только own data
descriptors; direct store дополнительно требует writable. Это исключает
неверное lowering при подготовке кода, без нового hot-path guard.

Регрессия сравнивает `[40000,-17500,60000,900000,100000]` с interpreter,
доказывает реальное splicing `readField`, optimizing execution и отдельный
native-вход getter без compile/deopt. Дополнительно 108 запусков минимальных
воспроизводителей и полного корпуса совпали с Node: 60 повторов native и
48 проверок stress 1–16 в native/Template/interpreter.

Старый integration test ожидал массовой отмены callers при retraining leaf,
хотя текущая политика сохраняет их до собственной неудачной проверки.
Тест теперь проверяет точные warmup generations, по одному ShapeGuard
после выхода leaf, ноль caller invalidations и отдельные native-входы
замещающих поколений. Все 14 integration tests прошли.
