# Native regexp matcher: hot programs run as machine code

Parent `aaa681466`. Machine provenance: [gate-summary.json](gate-summary.json),
[performance.json](performance.json), wall-clock `wall-final/`.

## Удалённый механизм

Каждый поиск шёл через интерпретатор байткода `backtrack::run`. Для каждой
стартовой позиции Rust-цикл `Matches::next` выбирал кандидата и вызывал
`attempt`. Тот сбрасывал слоты захвата и стек, затем диспетчеризовал
`Insn` по одной; каждый откат проходил через `match` по `Resume`. В профиле
regexp-фикстуры это 31.7% сэмплов (`run` 18.6% + `next` 13.1%).

Теперь регэксп, найденный в поиске 8 раз, компилирует программу в машинный
код — один раз на ширину субъекта (байты Latin-1 / UTF-16), dynasm, AArch64
и x86-64 (`exec/native/`):

- **Одна функция обходит окно кандидатов целиком.** Она сама:
  - фильтрует старты по 256-байтной таблице первого множества;
  - сбрасывает слоты;
  - ведёт попытку и откаты;
  - пропускает possessive-прогон лидирующего повтора.

  В Rust возвращается только матч, исчерпанное окно или исчерпанный бюджет
  шагов.
- **Окна.** Векторный поиск (memmem / memchr / memchr2/3) находит первого
  кандидата, код — остальных по той же таблице. У обязательного литерала
  окно — все старты, которые допускает вхождение.
- **Откат.** Кадры `[resume, pos, log mark, aux]` лежат в растущем стеке,
  журнал отмены `[slot, old]`, рост — через Rust-хелперы. Пары
  Split/Repeat — тот же порядок кадров, что у интерпретатора.
- **Прогоны.** Подряд идущие Char/CharSeq/Class/AnyChar, в которые нет
  входа, проверяют длину один раз и читают единицы со смещений. CharSeq
  сравнивается по 8 байт.
- **Тесты единиц.** Таблицы для единиц < 0x100 строятся из предикатов
  интерпретатора. Для старших единиц — до 4 диапазонов inline, иначе вызов
  того же предиката.
- **Покрытие.** Код получают программы без `u`/`v` и без lookaround;
  остальные остаются на интерпретаторе.

Число шагов совпадает с интерпретатором точно: шаг на каждый снятый кадр,
включая вход в попытку, и шаг, превысивший бюджет. Поэтому бюджет обрывает
оба тира в одной и той же точке.

Попутно убраны три поштучных расхода:

- **ISB на каждое окно.** `prepare_for_execution` стоил 4.4% фикстуры.
  Теперь барьер ставится только когда код финализирован другим потоком
  (тег потока из `tpidrro_el0` / `tpidr_el0`).
- **`MatchScratch` по значению.** 256 байт переносились 4–5 раз на поиск
  (`Cell::take/set`, в `Matches` и обратно). Теперь это `Option<Box<…>>`.
- **Обязательный литерал в UTF-16.** Поиск «редкой» единицы через SWAR
  плюс `eq_units` на каждый кандидат заменён на `memmem` по байтовому виду
  `&[u16]`; попадания по нечётному смещению отбрасываются. Для Latin-1 —
  тот же `memmem`.

## Исправленная ошибка семантики (оба тира)

Класс без `u`/`v` с флагом `i` замыкался только по ASCII-регистру:
`/[à-ÿ]/i` не матчил `À`–`Þ` и `Ÿ`. По §22.2.2.9 CharacterSetMatcher
символ подходит, если `Canonicalize` какого-то элемента класса равен
`Canonicalize(ch)`. Теперь build.rs группирует все BMP-единицы по
каноническому виду (`CANON_GROUPS`). Lowering замыкает класс по этим
группам (`fold_canonical_case`), и проверка остаётся простым членством.

Ошибку нашёл новый difftest-корпус `regexp_native_matcher` (паттерн 16 расходился с
node и на старом бинаре). Unit-тест сверяет группы с `canonicalize` на всех
65 536 единицах.
