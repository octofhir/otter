# Неизменяемый тип receiver в Graph

Повторные чтения array.length в узком native-сценарии: **-8.49% … -5.90% wall** в трёх сериях по пять samples; инструкции **-13.09%**. Полная wall-матрица не подтверждает общий выигрыш: первая серия дала **+4,17%**, чередующийся контроль **−3,44%**, при дрейфе неизменного Node от **-26.75% до +208.36%**. Эти широкие wall-дельты сохранены как наблюдения и помечены `scoreable: false`. FW по 13 фикстурам практически неизменен: **+0.048%**, o/node **1,8413 → 1,8421**.

## Механизм и корректность

Физический тип `ObjectBody` / `ArrayBody` теперь известен сразу после соответствующего создания. У массива тот же факт появляется после успешного guarded чтения length. Факт принадлежит конкретному SSA value, пересекается на joins и сохраняется через callbacks и moving GC. Semantic Object / Array.isArray его не заменяют: Proxy и callable остаются отдельными представлениями.

Обычные object births, включая globalThis и intrinsic Object(), убирают шесть pointer/type-инструкций перед первым CheckShapes; живой shape продолжает проверяться. Array births, включая intrinsic Array() и new Array(length), и последующие length-чтения доказанного receiver убирают те же повторные проверки. На ARM64 LoadArrayLength сокращается с 10 до 4 инструкций до учёта register moves/spills. Обе архитектуры сохраняют полную 64-битную проверку length < 2³¹; значение не усекается перед guard. В свежих code-map regions неизвестный receiver занимает 44 байта с move, доказанный — 20 с move или 16 без него. Header и ABI не выросли, новых runtime-флагов и совместимых форматов нет.

Runtime-пруфы исполняют isolated probe в том же установленном Graph-поколении: callback изменяет length и поле, затем вызывает moving GC; массив, объект и молодой child читаются корректно, collector действительно переписывает slots. В default и дополнительном realm нет interpreter ticks тела или смены поколения на успешном probe. Length 2³¹ вызывает eager-exit после callback, счётчик callback увеличивается ровно один раз. Реальные native code-map regions и IR проверяются вместе.

Scoped native запись Array.length использует существующий canonical Set с range/writability-правилами для строкового ключа и interned atom. Корпус дополнительно проверяет prototype/layout changes, сохранённые молодые ссылки, живую length после effect, замену SSA receiver, ordinary getter и Proxy с однократными observable чтениями.

Медиана пяти свежих процессов для каждого бинаря и каждой фикстуры. Сохранённый родительский бинарь и текущий выполняются последовательно, порядок бинарей чередуется по фикстурам; перед каждой серией нет активных Otter-процессов. Для четырёх прежних Bun-отказов сводка скрипта на одной фикстуре делит на ноль после записи корректных Otter/Node samples; wrapper отдельно проверяет все пять exit codes, сохраняет ошибку сводки и не включает неуспешный Bun в score. Эти восемь ошибок сводки явно перечислены в `gate-summary.json`.

## Узкий native wall-пруф

50 млн вызовов `lengths(receiver) { return receiver.length + receiver.length; }` на одном массиве `[1, 2, 3]`, normal production policy. Все результаты равны Node (`300000000`). Три серии parent/current с чередованием порядка, по пять свежих процессов на бинарь в каждой. Source и все 30 samples сохранены в `performance.json`.
