# Loop entry facts: peeled first iteration, invariant conversions, untagged exits

Parent `c9959798f`. Machine provenance:

## Обязательная работа, которая исчезла

- Цикл, который вызывает наружу, терял все факты о куче на заголовке. Если
  receiver (`this`, инвариантный регистр) впервые доказывался внутри цикла —
  deltablue `Plan.execute`, richards `Scheduler.schedule` (OSR-вход без
  фактов) — полная проверка формы шла на каждой итерации.
- Слияние ветвей полиморфного вызова теряло доказательство формы, если одна
  ветка держала его «свежим», а другая — stale после вызова.
- Phi, вход в который — выход из ранней итерации и выход из цикла, держал
  tagged-значение: правило «tagged phi не читает untagged phi» оставляло
  счётчики и переносы в цикле боксированными (CheckedTaggedToInt32 + бокс
  каждую итерацию).
- LICM не выносил конверсии инвариантных чисел (`CheckedTaggedToInt32/
  Float64/Index`, `CheckNumber`) из циклов без вызовов.

## Архитектура

- `builder_peel`: innermost цикл без handlers, который вызывает наружу и
  читает инвариантный receiver или `this`, получает первую итерацию в
  вторых слотах блоков. Все входы извне (OSR тоже) идут в неё; latch'и
  входят в настоящий цикл прямыми рёбрами. Если вход уже доказывает все
  receiver'ы, рёбра перенаправляются в настоящий header.
- Заголовок цикла оставляет только факты об узлах, достижимых из регистров
  и `this` (и значений их известных полей).
- `Known::intersect`: stale-доказательство стабильных форм держится там, где
  другое ребро доказывает те же формы напрямую.
- `phi_repr`: tagged phi читает untagged phi через бокс в конце
  предшественника.
- LICM переносит конверсии инвариантов в pre-header (кроме header'ов, уже
  выходивших по TypeMismatch).
