## Цель

1. Geomean otter/node ≤ 1.0, otter/bun ≤ 1.0. Промежуточная веха: ни
   одна фикстура не хуже 1.5× node.
2. RSS не выше node на каждой фикстуре: splay, ts, gbemu, mandreel.
3. Стартап `hello.js` и `empty.js` не хуже bun: время и инструкции
   через `/usr/bin/time -l`. Первым делом сними текущие числа.

## Как работать

- Каждый пункт начинается с исследования. В `~/work/engines` лежат
  исходники v8, WebKit, gecko-dev и graal. Прочитай, как подсистема
  устроена там, и портируй архитектуру, а не придумывай эвристику.
  Профилирование только задаёт порядок работ, это не метод. В коде,
  комментариях, именах и коммитах другие движки не называть.
- Профили: `scripts/dev/sample_kind_prof.py`, `launchprof.py`,
  `prof_top.py`, `native_hot.py`, `step_count.py`, `hot_asm.py`,
  `graph_disasm.py`. Доли профиля не выдавать за выигрыш: выигрыш
  считается только по wall-clock.
- Нужны крупные архитектурные изменения, а не цепочки правок на пару
  процентов. Если изменение большое, режь его на вертикальные шаги:
  каждый шаг проходит проверки, коммитится отдельно и ничего не
  регрессирует.
- После каждого коммита обновляй файл сессии в памяти: что сделано,
  цифры, ловушки. Затем бери следующий пункт по разрыву в матрице.

## Направления (порядок — по разрыву, пересматривать после каждой матрицы)

1. **Shape в заголовке ячейки.** Это основа для property access во всех
   тирах. Сейчас `CheckShapes` в graph-тире ARM64 занимает ~10 инструкций,
   а должен 3–4. У каждого типа ячейки идентификатор формы лежит в одном
   фиксированном слове заголовка. Объём работ: заголовок `otter-gc`,
   форвардинг скавенджера, стабы аллокации, snapshot/heap image,
   эмиттеры template/graph arm64 и x86, `LoadArrayLength`. Детали — в
   `PROMPT_HARD_REFACTOR_5.md`.
2. **Вызовы в JIT-тирах** (deltablue 3.55, richards, box2d). Разобрать
   полную стоимость вызова в template и graph:
   - пролог и эпилог;
   - проверка цели;
   - передача аргументов;
   - арности и rest;
   - возврат.

   Сравнить с прологом и call IC эталонных движков. Ещё:
   - полиморфные call IC;
   - инлайнинг полиморфных целей;
   - вызовы методов через прототип;
   - `call_generic_entry` и native-call glue без входа в Rust;
   - `f(...args)` — отдельный опкод во всех тирах, без временного массива.
3. **GC и аллокации** (splay, raytrace, box2d, ts; RSS splay 570 против
   404 у node):
   - эвристики роста young/old;
   - pretenuring по allocation site;
   - escape analysis и scalar replacement в graph-тире для временных
     объектов (raytrace/box2d создают векторы);
   - конкурентная маркировка old-gen;
   - размеры ячеек.
4. **ts** (2.89, самая длинная фикстура):
   - мегаморфные загрузки (megamorphic stub cache);
   - строковые операции;
   - Map/Set;
   - замыкания;
   - tier-up: пороги, OSR, latency фоновой компиляции;
   - деопт-штормы.

   Профиль по видам узлов покажет, что из этого дорого.
5. **RegExp** (3.41 node, 4.56 bun): построение результата exec (было
   4.6× node), `replace`/`split` glue, JIT-компиляция паттернов. Эталон
   для строк и регулярок — JSC.
6. **Интерпретатор и baseline**: вызов 1766 → ≤1200 инструкций; пороги
   tier-up, чтобы горячий код быстрее уходил из интерпретатора.
7. **Graph-тир как оптимизирующий компилятор**. Сверить с эталонами
   полноту пайплайна:
   - global value numbering;
   - LICM;
   - bounds-check elimination;
   - range analysis;
   - распределение регистров;
   - type speculation для Int32 и Double;
   - loop peeling.

   Упрощённые алгоритмы запрещены. Покрытие опкодов наращивать можно.
8. **Стартап**: снапшот, ленивая инициализация web/node-поверхности,
   стоимость первого `console.log`.

## Проверки

- Пока итерируешь — лёгкие проверки:
  - clippy затронутых крейтов;
  - `cargo test --release -p <crate> --lib` затронутых крейтов;
  - один-два затронутых `--test` в otter-runtime;
  - difftest-корпус против node (`scripts/dev/quick_difftest.py`);
  - узкий фильтр test262 по затронутой области.
- Перед каждым коммитом JIT/GC/VM — полный test262 одним runner'ом в фоне
  (`bash scripts/test262-full-run.sh > test262_results/full-run-<date><n>.log`,
  `timeout: 7200000`). Набор падений должен совпасть с базовым.
- На вехах (раз в несколько коммитов) — тяжёлый гейт из
  `PROMPT_HARD_REFACTOR_5.md`:
  - x86 clippy и тесты через Rosetta;
  - difftest x86;
  - oracle, gc и gcfull;
  - checked GC.
- Замеры:
  - `scripts/dev/wallclock_matrix.sh <bin> <out> 5` — только на тихой
    машине (проверять `uptime`), после окончания тестов;
  - сравнение с parent-бинарём на затронутых фикстурах — 3×5 вперемешку;
  - инструкции — только как диагностика.
- В коммит идут цифры до/после и load average замера.

## Жёсткие правила

- Только main: без веток, worktree, stash, checkout, reset. Чужие
  untracked-файлы не трогать. Незакоммиченные hunks — твоя работа:
  доделать и закоммитить.
- Без env-флагов и feature toggles, без `thread_local!`, `static mut` и
  process-global состояния. Без Rc и счётчиков ссылок вместо стабильных
  адресов. Без bridges, адаптеров и слоёв совместимости: внутренний
  контракт менять на месте.
- GC roots, деопт, исключения и порядок эффектов сохранять. Многоаллокационные
  нативы — через handle scopes, проверять под `OTTER_GC_STRESS`.
- Тесты: расширять существующие, новые — только для реального бага
  механизма. Устаревшие тесты, проверяющие неактуальный контракт,
  удалять. Никогда `cargo test --workspace` и пачки `--test`.
- rustfmt — только leaf-файлы (`rustfmt --edition 2024 <file>`); для
  `lib.rs`/`mod.rs` — `--check`.
- Коммиты:
  - автор: `git -c user.name="Alexander Streltsov" -c user.email="funyloony@gmail.com"`;
  - GPG-подпись, проверить `G`;
  - никаких Co-Authored-By и AI-trailer;
  - коммитить отдельным вызовом, только после просмотра вывода тестов;
  - в сообщении нет «осталось / не сделано».
- Файлы — только в репозитории: `scripts/dev`, `benchmarks/results/<slice>`.
  Не в /tmp. Design-doc и research-.md не писать: код и измеренная дельта.
- Диск ~95%: проверять `df -h /System/Volumes/Data`. Если меньше 15 GB —
  удалять `target/*/incremental`, `*.rcgu.o`, `target/x86_64-apple-darwin`.
  Нужные бинари сначала сохранить. Никогда `cargo clean --target`.
- Перед копированием поверх бинаря на macOS сначала удалить destination.
- Для нового или существенно изменённого Rust-модуля — точные `//!` docs:
  назначение, `# Contents`, `# Invariants`, `# See also`.

Не останавливайся: после каждого коммита — следующая матрица, следующий
разрыв, следующий пункт.
