## Earlier Math result and current four mechanisms

Earlier `math-intrinsics` ProductionTiered: 276.670125 → 6.5920415 ms (**41.97×**) after Int32 method lowering.
Runtime-stub transitions per invocation fell from 1,200,094.535714 to 97.642857.
Optimized deopts stayed zero. That earlier package left `native-boundary` at 280.345104 → 281.9065415 ms; this is a specialized-kernel result.

The current package addresses four separately identified boundaries:

1. Resolved `CallWithThis` reuses the method/native identity + Int32 Math CFG;
   cold completion retains the loaded callee and receiver without another lookup.
2. IC attachment uses existing rooted dictionary-to-shape preparation before the
   first optimizing snapshot; no refresh/recompile policy was added.
3. Shared VM/JIT ordinary slot proofs permit benign sidecars while checking fast state,
   descriptor overrides and opaque host/mapped/String lookup semantics.
4. Both backends probe the existing fixed 1,024-entry shape/atom cache for
   megamorphic own/direct-prototype data loads, then read the live slot.
   Negative/deeper/exotic entries use the existing rooted cold call; stores are
   unchanged. No second cache, larger PIC, new call ABI or replay path was added.

## Primary-source design comparison

[SpiderMonkey's shared cache](https://raw.githubusercontent.com/mozilla-firefox/firefox/main/js/src/vm/Caches.h) uses shape/key metadata and a separate store cache;
[Watchtower](https://raw.githubusercontent.com/mozilla-firefox/firefox/main/js/src/vm/Watchtower.cpp) invalidates broader prototype proofs.
[V8's generated probe](https://raw.githubusercontent.com/v8/v8/main/src/ic/accessor-assembler.cc) checks name/map and reads live fields;
[prototype handlers](https://raw.githubusercontent.com/v8/v8/main/src/ic/handler-configuration.cc) carry validity checks.
Otter's bounded live-holder proof fits this family; deeper/negative hits need additional proof.
Source research only: no cross-engine benchmarks or copied code.
