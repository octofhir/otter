# Parallel young-generation scavenge

Parent `ba4b85400`. Machine provenance: [gate-summary.json](gate-summary.json),
[performance.json](performance.json), wall-clock `wall-final/`. CLI
`a414bbdffb45b7c6dcf994787a2a1a8dcc36010a7a1f12234af5b86f87afec82`.

## Удалённый механизм

Последовательный Cheney-скавенджер: один поток копировал и трассировал всех
выживших, сканируя to-space страницы и список промоутированных. Минорный GC
на главном потоке splay (`sample`, 1 ms): 276 из 717 сэмплов (38.5%) →
101 из 503 (20.1%).

## Архитектура

- `otter-gc/src/gc_threads.rs`: помощники кучи (`min(cores − 1, 3)`,
  стартуют на первом скавендже с ≥ 1 MiB входа), задача исполняется на всех
  помощниках и на собирающем потоке, паника в задаче — abort. Ничего общего
  между кучами.
- Скавендж: корни эвакуирует собирающий поток последовательно (корневые
  визиторы работают как раньше); затем все потоки разбирают чанки
  remembered parents (бит сбрасывается перед трассировкой родителя) и
  worklist-ы копий; поток с длинным списком отдаёт половину простаивающим;
  фаза кончается, когда все простаивают и общих чанков нет. Эфемероны,
  weak-слоты, финализация, age mark и flip — последовательно.
- Захват ячейки: CAS байта флагов ставит forwarded + copying (новый бит 7);
  захвативший копирует, пишет смещение, снимает copying с release;
  остальные ждут и переписывают слот на опубликованную копию. Слоты читаются
  и пишутся relaxed-атомарно.
- Аллокация: to-space страницы по атомарному индексу (страница — одного
  потока, bump через сырые поля заголовка страницы); промоушен ≤ 2 KiB — в
  линейную область потока из old space (`take_lab`: дыра free-list ≥ 32 KiB,
  дыра ≥ объекта, хвост новейшей открытой страницы, свежая страница — без
  сканирования страниц), крупнее — под замком. Резерв промоушена учитывает
  страницу и область каждого потока.
- Счётчики allocation sites инкрементируются атомарно из потоков.
