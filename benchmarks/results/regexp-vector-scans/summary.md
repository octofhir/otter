# RegExp vector scans: memchr/memmem over one-byte subjects, SWAR over UTF-16

Parent `632fb10e4`. Machine provenance: [gate-summary.json](gate-summary.json),
[performance.json](performance.json), wall-clock `wall-final/`.

## Удалённый механизм

Leftmost-поиск отбрасывал невозможные стартовые позиции скалярными циклами:

- **Обязательный литерал** (`RequiredLiteral`): поиск одной «редкой» единицы
  поэлементным сравнением, затем сверка всего литерала, при промахе — снова
  с `start + 1`.
- **Первое множество** (`Prefilter`) из 2–3 байтов: табличная проверка
  каждой позиции по одной.
- **Одиночная единица** (`single`) и repeat-скан: поэлементное
  `iter().position`, которое для `u16` компилятор не векторизует.

Теперь:

- **Однобайтовый субъект + Latin-1 литерал**: `memchr::memmem::Finder`,
  построенный один раз при lowering, ищет литерал целиком.
- **Первое множество ≤ 3 байтов** на однобайтовом субъекте:
  `memchr` / `memchr2` / `memchr3`.
- **`Unit::position`**: для `u8` — `memchr`, для `u16` — SWAR-скан по 4
  единицы в слове (`(x ^ splat) - 0x0001…` & `!x` & `0x8000…`), хвост
  поэлементно.
- **`Unit::as_latin1`** даёт байтовый срез однобайтового субъекта, так что
  выбор векторного пути — одно сравнение типа при старте поиска.

Новая зависимость otter-regex — `memchr` (уже в графе workspace).
